# Elf Girl Pinball (Steam App ID 2074890) 종료 진단

기록일: 2026-10-12. 기기: iPad Air M3, iPadOS 26.3, Madeira Dev 0.1.3. 사용자가 게임을 실행한 직후 Madeira Dev가 종료된 로그를 USB 연결로 읽었다. 이 기록은 **종료 원인 진단**이며, 수정 빌드 테스트는 하지 않았다.

## 확인된 사실

- 22:08:35에 Steam App ID `2074890` 실행을 요청했다. Madeira가 JIT를 켰고, Steam Dock은 게임 실행 파일 `Elf Girl Pinball.exe`를 띄웠다. 게임 창 `Elf Girl Pinball`과 렌더링 프레임이 확인된다. 설치 스크립트는 0개였다.
- 서명된 Dev 앱의 `increased-memory-limit` 권한은 `true`였다. 이번 종료는 JIT가 꺼져 있거나 32비트 Wine DLL이 없어서 게임 프로세스가 시작하지 못한 경우와 다르다.
- DXMT 메모리 계측의 마지막 값: `tex-private` **5,084 MiB**(할당 3,544건, 해제 2건), `staging-ring` **964 MiB**, DXMT 합계 **6,058 MiB**. Metal의 `currentAllocatedSize`는 **5,841 MiB**였다. iOS 프로세스의 마지막 기록된 `phys_footprint`는 **7,636 MiB**였고, 시작 때 앱이 기록한 기기 RAM은 **7,623 MiB**였다. 이 수치는 서로 다른 메모리 지표이므로 단순 합산하지 않는다.
- `tex-private`는 DXMT의 Metal 텍스처 할당 계측 범주다. 수 초 동안 계속 증가했고, 거의 해제되지 않았다. 일부 BC 압축 텍스처는 로그에서 251,381 KiB(약 245 MiB)의 논리 크기로 집계됐다. 따라서 이 BC 텍스처 집계만으로 약 5 GiB의 전체 텍스처 증가를 설명할 수 없다.
- 마지막 앱 로그는 `NtWaitForAlertByThreadId [alert-storm]`에서 끊긴다. 게임의 명시적 종료 코드나 해당 시각의 Madeira 충돌 보고서는 확인되지 않았다. iPad의 `JetsamEvent` 목록에도 새 보고서는 없었다.

## 판단과 한계

**가장 유력한 원인은 메모리 압박으로 인한 iPadOS의 앱 종료**다. 게임 창이 나온 뒤 Metal 텍스처 사용량과 프로세스 footprint가 급격히 증가했고, 그 직후 앱 로그가 예고 없이 끊겼다. Memory+ 권한이 있어도 사용량이 계속 늘면 종료될 수 있다. 다만 이 실행에 대응하는 Jetsam 보고서가 없으므로 시스템의 실제 종료 사유를 확정하지 않는다.

할당 3,544건에 해제 2건이라는 수치만으로 **게임이 자산을 계속 보유하는지, DXMT가 자원을 잘못 유지하는지**는 구분할 수 없다. 로그의 `Failed to mprotect last page of code buffer` 메시지는 종료 훨씬 전부터 있었고 그 뒤 게임이 계속 진행했으므로, 이것을 직접적인 종료 원인으로 판단하지 않는다. 소스의 D3D11 자동 BC mip 제한은 64비트 게임에서 기본으로 켜지지 않지만, 이번 메모리 증가가 BC 텍스처만의 문제라는 증거도 없다.

## 다음 검증에 필요한 것

1. 동일 장면에서 시스템 Jetsam 보고서 또는 메모리 종료 사유를 확보한다.
2. DXMT 텍스처 할당의 크기·형식·생성 호출 지점과 해제 시점을 표본으로 기록해, 증가분의 실제 소유자를 구분한다.
3. 자원 종류가 확인된 뒤에만 텍스처 품질·mip 제한이나 자원 해제 수정을 한 번에 하나씩 비교한다. 현재 앱 설정이나 게임 파일은 이 진단 과정에서 바꾸지 않았다.

원본 앱 로그는 Mac의 `/tmp/madeira-current-game-log.txt`로 가져왔다. 임시 파일이며 계정 관련 내용이 포함될 수 있어 공개 저장소에 넣지 않았다.
